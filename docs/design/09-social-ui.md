# 用户界面与用户体验 (UI/UX)

## 入口与序章界面（登录 / 注册 / 序章）

登录、注册与开局序章是玩家进入游戏的第一印象，须在「复古极简（CRT 终端）」风格下集中体现游戏亮点。这些页面共用一套**终端控制台（console）框架**，避免重复实现。

- **共享框架组件**：`frontend/src/components/ConsoleFrame.vue`，提供「标题栏 + CRT 扫描线 + 内容插槽」。属性：`title`（屏幕名）、`status`（默认 `ONLINE`）、`maxWidth`（默认 `64rem`）。
  - 标题栏：三枚状态点（`--color-defeat` / `--warning` / `--accent`）、标题文案 `挂机英雄团 / <屏幕名>`（屏幕名用 `--accent` 高亮）、状态文案 + 闪烁光标（`_`）。**不使用伪 URL**，避免误导玩家以为是可访问地址。
  - CRT 扫描线：使用 `--bg-hover` 重复线性渐变叠加层（`pointer-events: none`），强化荧光屏质感。
- **登录 / 注册**：`frontend/src/components/AuthLayout.vue` 包裹 `ConsoleFrame`（`title` = 「登录」/「注册」），左栏展示亮点、右插槽放入各页表单（保持表单字段、按钮文案与既有 E2E 选择器不变）。
- **序章（onboarding）**：`frontend/src/views/IntroPage.vue` 直接用 `ConsoleFrame`（`title` = 「序章」）包裹三步流程（欢迎 → 命名 → 出发）。步骤指示器为终端式标签（`> ` 进行中 / `+ ` 已完成），表单 label 加 `> ` 前缀，沿用与登录页一致的终端输入框风格；步骤标题文案（如「欢迎来到挂机英雄团」「为你的队伍起个名字」「你的初始队伍」）保持不变以兼容 E2E。**队名步**仅自由输入（无预设推荐名），配合全服唯一校验。
- **主体两栏**（窄屏 ≤860px 自动堆叠）：
  - **左栏（游戏亮点展示）**：终端启动提示行 → 标题块（kicker「文字策略放置 RPG」+ 主标题「挂机英雄团」带发光呼吸动画 + 标语）→ **开局铁三角条**（坦克 `--color-phys` / 输出 `--color-magic` / 治疗 `--color-heal`，并标注「通关解锁招募 · 最多满编 5 人」以说明开局 3 人非最终阵容）→ 亮点列表（离线挂机、暗黑式装备词缀、极致透明机制，各项不重复）→ 落款行「灵感致敬 魔兽世界 · 暗黑破坏神 · 流放之路」。文案与 [01-overview.md](./01-overview.md)「关键特征」「独特卖点」「致敬经典」保持一致。
  - **右栏（表单）**：登录/注册表单，label 以 `> ` 前缀、输入框为终端风格（`--bg-darker` + `--border-dark`，focus 用 `--accent` + `--focus-glow`），底部为切换登录/注册的链接。
- **颜色与令牌**：全部复用 [11-ui-tokens.md](./11-ui-tokens.md) 既有令牌（背景层级、语义色、发光），不新增色值；装饰性符号一律使用 ASCII（`>`、`/`、`_`、`[ ]`），符合源码 ASCII 约束。

> 注：序章（IntroPage）与登录/注册共享 `ConsoleFrame` 外框与终端视觉语言，保证从注册/登录到开局序章的风格连续；开局固定三人（战法牧）流程与扩展招募规则仍以本文「小队规模与招募」及 [02-levels-monsters.md](./02-levels-monsters.md) 1.2 为准。

### 行动中高亮

战斗过程中，**出招**与**挨打**使用不同动效，避免两侧卡片看起来都是「放大 + 抖动」：

| 状态 | 视觉 |
|------|------|
| **行动中**（`acting`） | **绿色/强调色**描边与光晕；卡片向战场中央**前冲**（英雄向右、怪物向左），峰值略放大并提亮；无红色闪屏 |
| **受击**（`targetHit`，有 HP 伤害时） | **红色**描边与光晕；卡片向**外侧击退**（英雄向左、怪物向右），短暂**纵向压扁**模拟受击，红色背景快闪后淡出；未命中则无 `targetHit` |
| **目标切换**（`monsterTargetIntent` / 非冗余 `ot`） | 怪物卡 **「目标」行**为主：旧名淡出上移、琥珀箭头、新名自下弹入并加粗高亮；行框短暂琥珀放大；新目标英雄卡片次要向内微缩聚焦（`--warning`）；与日志揭示、目标切换音效同一步 |
| **战败**（`unitDefeated` 揭示步） | **红色**描边与光晕；卡片向**外侧倾倒**（英雄向左、怪物向右）并略下沉、去饱和，约 0.95s 后落入战败静态样式；「DEFEATED」角标弹入；战斗日志「DEFEATED!」行自左侧滑入并短暂红光；与阵亡音效同一步 |

施放者靠前冲 + 绿框表示出招；目标靠击退 + 红闪 + 压扁表示挨打，与面板浮动伤害数字同侧出现。目标切换以怪物卡「目标」行内**姓名变化**为主视觉，不与出招、挨打混用同一套动效。战败在致死伤害步之后的 reveal 步触发，承接受击动效并过渡到持续战败样式。

### 面板伤害/治疗数字动画

角色或怪物受到伤害或治疗时，在其卡片面板上显示浮动数字动画，提升感官反馈：

| 场景 | 显示内容 |
|------|----------|
| 受到普通攻击伤害 | 显示 **-X**（红色），X 为实际伤害值 |
| 受到技能伤害 | 在**目标**卡片上显示**技能名称** + **-X**（红色），X 为实际伤害值；施放者卡片不重复显示同名技能标签 |
| 受到技能治疗 | 显示**技能名称** + **+X**（绿色），X 为治疗量（在获得治疗的角色卡片上） |
| 无伤害的定向技能（如嘲讽） | 在**目标**卡片上短暂显示技能名称 |
| 仅作用于自身的 buff（如防御姿态） | 在**施放者**卡片上短暂显示技能名称 |
| 攻击未命中 / 被闪避 | 在**目标**卡片上显示**技能名（若有）** + **「未命中」**；标签使用警告色（`--warning`），与伤害红、治疗绿、技能施放色区分；普通攻击未命中时技能名行使用普通攻击色（`--color-log-basic`） |

**出招与挨打区分**：施放者通过「行动中高亮」（见上节）表示正在行动；命中与技能名集中在目标侧，避免两侧同时出现相同技能名造成混淆。未命中时不触发受击高亮（`targetHit`），仅显示未命中飘字。

动画效果：数字自卡片中心向上浮动并逐渐淡出，约 1.2 秒后消失。伤害数字为红色（`--error`），治疗数字为绿色（`--color-heal`）；技能施放名使用技能色；未命中标签使用警告色；技能名称（伤害/未命中）使用技能色并斜体显示（普通攻击名除外）。

## 战斗日志增强

### 战斗流程日志

每场战斗在日志中按以下顺序展示，各场战斗之间以分割线和换行分隔：

1. **地图进入描述**（仅进入新地图时）：每次进入新地图（首次加载、切换地图、击败 BOSS 解锁下一张）时，战斗日志先显示该地图的简短描述（如 "Arriving at Elwynn Forest: A peaceful woodland where young adventurers begin their journey..."），以带边框的区块呈现，停顿约 1.8 秒后再开始第一场遭遇
2. **遭遇说明**：战斗开始时显示"Your adventure party encountered XXX!"（Boss 遭遇追加 "fearsome"），以金色斜体呈现；其中怪物名称按 Tier 着色，与战斗日志中怪物姓名颜色一致（Normal/Elite/Boss）
3. **回合日志**：逐条动画显示每次行动，包含详细伤害计算过程
4. **战斗总结**：胜利/失败/平局的总结性描述，含击杀怪物数、回合数、奖励信息
5. **休息阶段**：胜利后显示休息过程，包含 HP/MP 恢复进度，直至"Rest complete"
6. **分割线**：下一场战斗开始前插入视觉分割线

### 姓名颜色

- 战斗日志中，玩家角色姓名统一使用其职业对应的 WoW 职业色（与英雄卡片一致）
- 怪物姓名按 Tier 使用不同颜色：Normal (#66aa88)、Elite (#cc88ff)、Boss (#ff6644)
- 怪物作为攻击者和被攻击者时颜色保持一致

### 伤害数字颜色

| 伤害类型 | 颜色 | 暴击表现 |
|----------|------|----------|
| 物理伤害 | 白色 (#dddddd) | 加粗 + CRIT! 标记 |
| 魔法伤害 | 蓝色 (#44aaff) | 加粗 + CRIT! 标记 |

### 出手顺序与敏捷

- **敏捷显示**：角色或怪物出手时，战斗日志中显示其敏捷数值，格式为 `(AGI N)`，紧跟在出手者姓名后，便于玩家清晰看到「敏捷高者先出手」的原则

### 战斗日志可读性

- **回合标记 [Rx]**：使用较高对比度颜色（#66aa88）与浅色背景，便于识别
- **连接词**（used、on、for）：使用 #88bb99 等可读色，避免与背景混淆
- **伤害类型**（physical）、（magic）：使用 #99ccaa 与浅色背景，与计算详情行区分
- **普通攻击**：战斗日志中普通攻击（basic）显示为白色 (#ffffff)，与技能名称（技能色）区分
- **技能名称与伤害**：技能使用时，技能名称与造成的伤害数值分别使用不同颜色显示，便于快速识别

### 伤害计算详情

每条伤害日志下方附带浅绿色 (#88aa88) 计算详情行，格式为：
`ATK(raw) - Armor(defVal) = final` 或 `ATK(base) x 1.5 - Armor(defVal) = final`（暴击时）
- ATK(raw)：攻击方原始伤害
- Armor(defVal)/Resist(defVal)：防守方护甲或抗性数值
- final：最终伤害

被攻击方 HP 变化：在计算详情下方以 HP 色显示 `{被攻击者姓名} HP: before -> after/max`，便于复盘时追踪目标血量变化。

### 护盾与治疗（效果行）

非直接伤害类技能不显示伤害公式行；在详情区使用**与伤害公式行相同的样式**（`log-calc` / 浅绿辅助色）展示效果摘要：

- **真言术：盾**：护盾最多可吸收量、持续回合数（例如：护盾最多可吸收 N 点伤害，持续 3 回合）
- **治疗**：回复目标或自身 X 点生命；若同一技能先造成伤害再自疗（如嗜血），伤害公式行在上，自疗效果行在下

### 战败单位突出显示

- **战斗日志**：当我方角色或怪物 HP 归零时，在对应伤害/DoT 条目**下一步**追加一条突出显示的「DEFEATED!」条目（占用与行动步相同的 reveal 间隔），使用 `--color-defeat` 语义色、加粗、带边框与淡红底，并播放自左侧滑入的揭示动画，便于快速识别战败时刻
- **英雄/怪物面板**：战败单位（HP ≤ 0）的卡片使用 `--color-defeat` 边框、降低透明度、淡红背景，并显示「DEFEATED」角标；在 `unitDefeated` 揭示步播放向外倾倒、去饱和的战败过渡动画（约 0.95s），与阵亡音效同步

### 暴击系统

- 英雄暴击率由职业系数决定：PhysCrit = 5 + Agi * k_PhysCrit，SpellCrit = 5 + Int * k_SpellCrit
- 怪物暴击率按 Tier：Normal 5%，Elite 10%，Boss 10%
- 暴击伤害倍率：1.5x

## 角色详情面板

点击英雄卡片弹出详情 Modal，布局为左右对齐（属性名左侧、数值右侧）。角色姓名使用浅色文字 (#eeffee)，职业标签使用对应的 WoW 职业色，两者颜色区分。

**Tab 分页**：角色详情弹窗分为「Attributes」与「Skills」两个 Tab，便于技能增多时独立展示、避免主区域过长或需滚动。

**属性与装备左右分栏**：Attributes Tab 内，一级属性+二级属性与装备槽位采用左右结构展示——左侧为属性区，右侧为装备区；窄屏（<520px）自动切换为上下堆叠。

| Tab | 内容 |
|------|------|
| Attributes | 基础信息（Level、HP、资源）、一级属性、二级属性、装备槽位、Debuffs |
| Skills | 已学技能列表（战士初始技能等）；增强过的技能显示增强次数（如 2/3）及增强后的 effectDesc；无技能时显示「No skills learned yet」 |

Attributes Tab 内布局：基础信息 | 左侧：一级属性+二级属性 | 右侧：10 个装备槽位（Main Hand、Off Hand、Helm、Body Armor、Gloves、Boots、Belt、Amulet、Ring×2）；双手武器装备于主手并占用副手，副手显示「—」不可装备。

- **HP 一致性**：基础信息区与二级属性区的 HP 必须使用同一公式（10 + Stam × k_HP + Level × 2）计算，数值保持一致
- 二级属性数值支持鼠标悬停显示计算公式（Tooltip），公式中包含实际属性值与最终结果
- N/A 的属性（如牧师的 PhysAtk）显示为 "-"

## 战斗自动化

- 无任何手动战斗按钮（已移除 Explore Normal/Elite、Start Encounter、Fight Zone Boss、Recover One Turn）
- **战斗暂停**：战斗日志区域提供暂停/继续按钮；暂停时日志滚动与战斗动画停留（含休息阶段步间等待）；**两场遭遇之间**在进入下一场前亦会等待继续，避免「零间隔」模式下暂停无法拦住下一场开战。
- 组件加载后自动启动战斗循环：遭遇说明 → 战斗 → 日志动画 → 战斗总结 → 自动休息（含日志） → 分割线 → 下一场战斗
- 战胜积累探索度，探索度满时自动挑战 BOSS
- 休息阶段**每一步**在日志中的间隔须与**战斗中每一次行动**的日志步间间隔**相同**（同一毫秒配置，见 [03-combat.md](./03-combat.md) 1.3、[13-player-statistics.md](./13-player-statistics.md) 7.5）；每步在日志中显示恢复进度
- 战败后同样进入恢复阶段（"Recovering from defeat..."），逐步恢复所有英雄 HP/MP 至满值后再开始下一场战斗

- **数据可视化设计**: 战斗日志语义着色、HP/资源进度条、探索度进度条

## 战斗数据统计面板（Analytics）

- **主界面**：仅在顶部栏（或紧邻金币/经验的固定区域）展示两项 **步数基准收益效率**（无「按回合」统计）；可按 **每 1/10/100 探索步** 切换展示倍率；**不**在主界面铺开其余统计图表或明细表（见 [13-player-statistics.md](./13-player-statistics.md) 7.0、7.4）。该区域需与周边静态信息区分：卡片边框层级、悬停时边框/外发光强调，并可辅以弱提示文案（如「详情」）表明可点开数据统计 Modal。
- **详情页**：小队与英雄维度的累计收益、伤害/治疗、按技能拆分、实际暴击率/命中率/躲闪率等；以**图表**（占比、趋势）为主，精确数值可按指标需要辅以表格或悬停提示；支持**清零**后自新战斗起重新累计。数据统计 Modal 宽度适中（约小于视口宽、有上限），**固定整体高度**、Tab 内容区内滚动，避免切换 Tab 时外框高度跳动；场次趋势图需容纳纵轴数值与多序列折线、图内图例及单场悬停数值。完整指标与口径见 [13-player-statistics.md](./13-player-statistics.md)。
- **入口**：点击主界面效率区域，或提供独立「统计」等按钮进入详情页（实现选其一为主入口即可）。
- **规范**：Tooltip 与说明区块遵循 [11-ui-tokens.md](./11-ui-tokens.md) 与 `frontend-tips-tooltips.mdc`。

## 显示规格与适配策略

- **目标平台**: 桌面端显示器，不再进行移动端适配。
- **目标比例**: 固定按 16:9 视觉舞台进行布局，界面以该比例为基准设计与实现。
- **分辨率**: 以 1920 x 1080（1080P）为设计基准，**不设最低分辨率门槛**；低于 1080P 的窗口仍可进入游戏，可能出现布局拥挤或滚动，属可接受范围。
- **布局原则**:
  - 所有核心页面以大屏信息密度为优先，不再为窄屏做断点重排。
  - 主界面采用固定舞台（16:9）+ 内容分栏布局，减少滚动依赖。
  - 在超宽或非 16:9 屏幕上，通过留边方式保持核心内容比例一致。

# 技术规格 (Technical Specification)

## 技术栈总览

| 层级 | 选型 | 说明 |
|------|------|------|
| 后端 | Go | 高并发、单二进制部署、生态成熟 |
| 前端 | Vue 3 | 组件化、响应式、适合复杂数据展示 |
| 数据库 | SQLite | 初期轻量部署，使用 GORM 便于后续迁移至 PostgreSQL |
| 通信 | REST + WebSocket | REST 常规接口，WebSocket 实时推送 |

## 后端 (Backend)

- **语言与框架**: Go + Gin / Fiber
- **选型理由**:
  - 原生并发支持（goroutine），适合多玩家、战斗结算、离线收益计算等场景
  - 单二进制部署，资源占用低，适合中小规模部署
  - Web 框架成熟，便于快速开发 REST API 与 WebSocket 服务
- **关键技术**:
  - WebSocket: gorilla/websocket 或 nhooyr.io/websocket（战斗日志、聊天等实时推送）
  - 离线收益: 服务端按离线时长计算，保证防作弊与数据一致性

## 前端 (Frontend)

- **框架**: Vue 3
- **选型理由**:
  - Composition API 便于组织战斗日志、数据统计等复杂逻辑
  - 响应式系统适合实时战斗面板、挂机收益统计等动态更新
  - 组件化适合拆解主界面、战斗、角色、背包等模块
- **技术建议**:
  - 状态管理: Pinia
  - 路由: Vue Router
  - UI 风格: 复古像素风（见下方界面美术风格）
  - 显示规格: 桌面端 16:9 基准布局，不设最低分辨率门槛，不提供移动端响应式断点

## 数据库 (Database)

- **选型**: SQLite（MVP / Alpha 阶段）
- **适用场景**: 单服部署、玩家量级较小、读写并发不高
- **注意事项**:
  - SQLite 为单写锁，高并发写入时会排队
  - 若 Beta / 正式版预期玩家增多或需多服部署，可迁移至 PostgreSQL
- **ORM**: GORM（支持 SQLite 与 PostgreSQL，迁移时仅需调整连接配置）

## 客户端/服务端架构

- **架构模式**: 前后端分离，前端 SPA + 后端 API 服务
- **离线收益**: 服务端权威计算，客户端仅展示与上报在线/离线状态
- **实时通信**: 战斗日志、聊天等通过 WebSocket 推送；排行榜、交易等可先采用 REST + 定时刷新

## 界面美术风格

- **设计令牌**: 颜色、字体、间距等具体实现规范见 [11-ui-tokens.md](./11-ui-tokens.md)，所有 UI 代码必须使用 CSS 变量，禁止硬编码色值。
- **整体风格**: 黑底绿字怀旧电脑风格（CRT 终端风格），与「复古极简美学」设计理念一致
- **实现要点**:
  - **配色方案**: 
    - 背景：纯黑色 (#000000)
    - 主文字：绿色 (#00ff88)，营造 CRT 显示器效果
    - 边框：绿色，使用 1-2px 实线
    - 强调色：亮绿色 (#00ffaa) 用于高亮和交互元素
    - 错误/警告：红色 (#ff6666) 用于错误，橙色 (#ffcc66) 用于警告
    - **语义色扩展**（用于战斗信息差异化显示）：
      - HP 条与数字：颜色随受伤程度变化，健康(>75%)绿(#44ff88)、受伤(26-75%)黄(#ffdd66)、重伤(1-25%)红(#ff4444)、死亡灰(#888888)
      - MP 条：蓝色 (#44aaff)
      - 物理伤害：橙色 (#ffaa44)
      - 魔法伤害：紫色 (#cc88ff)
      - 技能标注：黄色 (#ffee66)
      - 胜利结果：青色 (#00ffcc)
      - 失败结果：红色 (#ff4444)
      - 金币：金黄色 (#ffcc44)
      - 经验：浅绿色 (#88ffaa)
      - Boss：橙红色 (#ff6644)
  - **滚动条**: 自定义样式匹配暗绿终端主题（6px 窄滚动条，暗色轨道 #0a0a0a，绿色滑块 #1a3a1a，悬浮 #2a5a2a）
  - **字体**: 像素字体（如 Press Start 2P、VT323、Silkscreen）或等宽字体，强化终端感
  - **视觉效果**: 
    - 可添加轻微的文字发光效果（text-shadow）模拟 CRT 荧光
    - 边框使用简洁的实线，避免过度装饰
    - 保持简洁的布局，强化「命令行终端」的怀旧感
  - **图像**: `image-rendering: pixelated` 或 `crisp-edges` 保持像素图不模糊
  - **布局**: 网格化、固定宽高，强化「格子感」和「终端窗口」感

## 防作弊策略

- **核心原则**: 所有关键数值在服务端计算，客户端仅负责展示与输入
- **具体措施**:
  - 战斗结算、装备掉落、离线收益等逻辑全部在服务端执行
  - 客户端不参与任何权威数值计算，仅接收服务端结果并展示
